## オーナーに見てほしい6つの判断

ここだけ確認していただければ `W1-12` は完了です。**「後から変えると作り直しになる」のはこの6点です。**

### ① 率（FG%など）を保存せず、実数だけ保存する

`player_season_stats` には「成功数」と「試投数」を入れ、**FG% は保存しません。** 率は表示のときに計算します。

**理由:** 率を保存すると、**「試投0本」と「0%」を区別できなくなります。**
1本も打っていない選手の FG% は 0% ではなく「算出不可」です。実数から計算すれば、
分母が0のときに「算出不可」と出せます（オーバーライド §8「欠損値を0扱いしない」）。

### ② チーム成績は公式値だけを入れる。個人成績の合計で代用しない

`team_season_stats` には、公式に発表された数字だけを入れます。

**理由:** 要件定義書の明文の指示です。個人成績を足し上げてもチーム成績にはなりません
（出場停止・怪我・トレードで数字が合わなくなります）。

### ③ シーズン途中の移籍は `stints` で分割する

1シーズンで2チームに在籍した選手は、**チームごとに成績の行を持ちます。**
シーズン合計は別の行として持ち、画面ではどちらも出せます。

**理由:** 「レイカーズ時代の成績」と「移籍後の成績」を分けて見られないと、比較の意味が薄れます。

### ④ 手動で直した値は、元データを上書きせず別に持つ

管理画面で数字を修正すると、`manual_overrides` に**修正値だけ**が入ります。元データは触りません。
表示するときに、元データの上に修正値を重ねます。

**理由:** 元データを上書きすると、**次に同期が走ったときに修正が消えます。**
別建てにすれば、何度同期しても手動修正は残ります。

### ⑤ 年齢の基準日は `seasons.regular_season_start_date`

各シーズンの開幕日を入れる列を必須で用意しました（`docs/DECISIONS.md` §1 の決定に対応）。

**未取得のシーズンは空のままにし、年齢を表示しません。** 推測で埋めません。
ロックアウトやパンデミックで開幕が変則だった年があるので、実際の日付を個別に確認して入れます。

### ⑥ 非公開にするテーブルを決めてあります

**誰でも読めるもの:** 選手・チーム・成績・ランキング規定など、サイトに出す情報
**読めないもの:** 手動修正の履歴、同期ログ、外部IDの対応表、問い合わせ記録
**本人だけ読めるもの:** お気に入り
**承認済みだけ公開:** 選手の画像（審査中・却下のものは出しません）

## 品質の担保

`npm run verify:schema` で、**制約が「書いてある」だけでなく「効いている」ことを毎回確認**しています。
CI でも push のたびに、使い捨てのデータベースへ実際に適用して検証します。

現在 **16項目すべて通過**しています。内訳:

- 21テーブルが揃っている / 不足も余分も無い
- 全テーブルでRLSが有効
- 運用系テーブルが匿名から読めない
- **不正なデータが実際に弾かれる**（9パターン）
  - 成功数が試投数を超える
  - 先発数が出場数を超える
  - 勝敗数の合計が試合数と合わない
  - カラーコードの形式が不正
  - 身長が非現実的
  - お気に入りが選手とチームの両方を指す
  - 同じシーズン合計行の二重登録
  - （正しいデータは通ることも確認）
- 更新時刻が自動で記録される
- 検証用データがDBに残らない

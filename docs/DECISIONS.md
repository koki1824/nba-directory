## W0-6 ［保留］4項目（決定日 2026-07-29 / オーナー承認済み）

### 1. シーズン当時年齢の基準日 = **そのシーズンの開幕日**

- **決定**: 「シーズン当時の年齢」は、**当該シーズンのレギュラーシーズン開幕日**時点の満年齢とする。
- 出典: 要件定義書 4.3「シーズン当時年齢の基準日は未確定。開幕日または固定日をユーザー承認後に採用する。」

**実装への影響（W1-5 / W1-7 で必ず反映すること）**

- `seasons` テーブルに **開幕日カラム（`regular_season_start_date`）を必ず持たせる。** 年齢計算がこの列に依存するため、後付けにしない。
- 開幕日は reference seed（`W1-7`）で全シーズン分を投入する。API から取得できる保証がないため、**seed を正とする**。
- ロックアウト・パンデミック等で開幕が変則だったシーズン（1998-99 / 2011-12 / 2019-20 / 2020-21 など）は、
  実際の開幕日を個別に確認して投入する。ここを推測値で埋めないこと。
- 開幕日が未投入のシーズンでは、年齢を **推測で埋めず `N/A`** とする（オーバーライド §8「0 / NULL / N/A / Not calculated を区別する」）。

**既知のトレードオフ（オーナー了承済み）**

Basketball Reference など英語圏の主要スタッツサイトは「シーズン終了年の2月1日時点」の年齢を採用しています。
本サイトは開幕日基準なので、**選手によっては他サイトと年齢が1歳ずれて見えます。**
`W2-13`（seed数値の抜き取り確認）や `W4-7`（実データ検証）で他サイトと突き合わせた際、
年齢の差異は不具合ではなく仕様です。混乱を避けるため、**選手詳細ページに「年齢はシーズン開幕日時点」と明記する**こと。

### 2. 選手比較の同時比較人数 = **2人固定**

- **決定**: 9/1 公開時点の選手比較は **2人固定**とする。
- 出典: 要件定義書「MVPは2人最適化。公開時の最大人数は最終確認」。モック `02_compare.jpg` も2列構成。

**実装への影響**

- UI（`W2-7`）とモバイル情報設計（`W2-11`）は2人前提で作ってよい。
- ただし**DBスキーマ・URLクエリ・型定義は3人以上を受けられる形で引く**（オーバーライド §0.1「仮枠を作らない」）。
  具体的には、比較対象を「2つの固定スロット」ではなく**選手IDの配列**として扱い、
  上限は表示層の定数（`MAX_COMPARE_PLAYERS = 2`）で制御する。公開後の人数拡張でデータ層を作り直さないため。

### 3. 仮サイト名 slug = **`nba-directory`**

- **決定**: URL・Vercelプロジェクト名・リポジトリ名をすべて `nba-directory` で統一する。
- 出典: 要件定義書「正式サイト名・ドメイン・最終ロゴデータは後日決定」［保留］。

**実装への影響**

- あくまで**仮**。正式サイト名の決定後に変更しうる。
- 表示名（`<title>` やヘッダー）にこの slug を直接使わないこと。表示名は差し替え可能な1箇所に集約する。
- ロゴ（`W1-4`）は、要件定義書の指示どおり**サイト名が変わってもシンボルを流用できる構造**にする。

### 4. プレーオフのランキング規定 = **全選手表示＋試合数明示**

- **決定**: プレーオフのランキングでは**独自の最低試合数を設けず、全選手を表示**し、**試合数を必ず併記**する。
- 出典: 要件定義書「プレーオフにレギュラーシーズンの58試合規定を流用しない。公式基準がない指標は全選手表示 + 試合数明示とする。」

**実装への影響**

- `ranking_rules`（`W1-5` / `W3-6`）は **RS と PO で別レコード**として持つ。PO 側は最低条件なしを表現できる形にする。
- ランキング画面（`W2-10`）は、PO のとき「最低条件なし・試合数を併記」と画面上に明示する。
- 公式基準が存在する PO 指標が見つかった場合は、この決定を上書きせず**追加の行として記録**してから実装する。
- レギュラーシーズン側の規定（58試合等）と公式例外の扱いは `W3-10` の対象であり、本決定の範囲外。
